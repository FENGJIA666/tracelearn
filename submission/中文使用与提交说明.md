# TraceLearn 使用与提交说明

TraceLearn 将“先预测 → 核对原文 → 改条件做实验 → 独立完成迁移题 → 导出记录”连成学习流程，首个课程是大学数据库基础。概念实验由确定性程序计算；本地 AI 负责材料问答和原文填空干扰项。v1.3 增加结论与原文检查、保存问答复开，并让实验、迁移题与原文保持一致。

## 先体验便携版

下载 [TraceLearn-Portable.html](https://github.com/FENGJIA666/tracelearn/releases/download/v1.3.0/TraceLearn-Portable.html)，包含20道原创题、原文、SQL与候选键实验、复习建议、历史评测查看和导出。这些功能不需要 Node、模型或 API 密钥。文件大小以最终下载文件为准。

下载后可尝试在浏览器打开。浏览器工具无法自动访问 `file://`，直接双击路径不作为已完成的自动化验收。也可在解压后的项目目录运行：

```sh
python3 -m http.server 4329 --bind 127.0.0.1 --directory submission
```

然后打开 <http://127.0.0.1:4329/TraceLearn-Portable.html>。这是本机静态预览，不是公开部署。便携版不运行模型，也不导入个人材料；真实 AI 功能需要完整本地应用。

## 核心体验

1. 用 **Quick tour** 进入 **Predict**。在 SQL NULL 题故意选择 **200 and NULL**、**Very sure**，体验反馈，再点击 **null-where** 核对原文。这是演示操作，不是真实学生实验。
2. 进入 **Experiment / Lab**，保留100、200、NULL三行，预测哪些行通过 `value <> 100`，再点 **Run & check prediction**。表格逐行显示 TRUE、FALSE、UNKNOWN，以及保留或排除的原因。
3. 改成 `value <> target OR value IS NULL` 并重新预测。也可改数据或改成 NOT IN，检查原来的结论在哪些条件下不成立。
4. 点 **Try a transfer question**，打开与当前实验条件或依赖模型匹配的迁移题及原文。NOT IN、默认 NULL 实验和第二个键模型各有对应内容；即使以前答过，也打开新的未作答状态。重新开始 Quick tour 会恢复初始实验。
5. Lab 导出 **TraceLearn-lab-record.md**，保留输入、预测、材料哈希和重新计算的结果。**Notebook** 可展开已保存题目和 AI 问答，刷新后仍可查看，无需重跑模型；问答保留当时的引用与检查状态。Notebook 另行导出学习报告，Lab 预测不计入题目正确率。
6. 在 **Keys & closure** 第一个关系中比较 A、AD 与 ABD：A 推不出 D，AD 是候选键，ABD 中的 B 可删除。第二个模型对应 Instructor 不是超键及3NF/BCNF迁移题。

Lab 不调用 AI，不支持任意 SQL，也不自动证明所有范式。它只计算四种 SQL 条件和两个给定依赖的关系模型。实验记录保留最近100条，存于浏览器并按原文哈希区分；清理浏览器数据可能删除记录，请导出重要记录。

## 完整本地 AI 与自己的材料

安装 **Node.js 22.13+ 和 Ollama 0.34.0+**，在项目目录运行：

```sh
npm run setup
npm start
```

CLI 默认地址为 <http://127.0.0.1:4317>。setup 在下载前检查 Ollama 版本；本版依赖已实际测试的聊天 `truncate:false` 行为，因此要求至少0.34.0。应用只需要 `qwen3.5:9b` 与 `qwen3-embedding:0.6b`，首次模型下载合计约 **7.234 GB**，另需依赖存储；这是下载体积，不是运行内存占用。模型权重不在源码包内。验证设备为 macOS / M4 Pro / 24 GB 内存，Ollama 0.34.0；Windows/Linux 尚未实测。

Mac 可用 **Start-TraceLearn.command**。它先重建当前副本，再检查版本、安装目录哈希与构建指纹。遇到其他副本或旧构建时，会保留原进程并在4317–4336选择空闲端口，终端显示实际地址。最终软件验证范围以 [v1.3验收记录](../evidence/v1.3/acceptance.md) 为准。

安装后无需 API 密钥、云端账号或付费推理。应用和模型都在本机运行；首次下载需联网，之后可在只允许本机连接的环境使用。公开源码不意味着把学习材料上传到云端，也没有公共推理服务。

**Ask the source** 先检索五段原文，由程序生成精确引文片段。模型给出一条完整、简短的结论及必要理由，并选最多两条片段；程序定位原文后，由同一模型另一次调用检查所求信息是否确定、结论与来源归属，以及适用条件是否完整。上下文上限16,384 token，输出上限1,800 token，`think:false`、`truncate:false`。超出上下文会明确拒绝，不悄悄丢弃原文。

结果区分为：`supported` 表示自动检查通过；`insufficient` 表示所选原文不足以确定完整答案；`unverified` 表示没有完整解释通过检查。自动检查不保证正确，也不是独立人工验证。问答最多两轮、四次模型调用，总请求限时180秒。取消会中止请求而不再次提交；切换课程或问题后，旧结果不能覆盖新界面。取消前已完成保存的回答仍可能留在历史中。

导入文本 PDF、UTF-8 Markdown 或 TXT，所有文件最多10 MB；PDF最多50页，Markdown/TXT最多175,000个 UTF-16 长度单位（常见 emoji 占两个）。扫描件需外部 OCR，多栏 PDF 需核对阅读顺序。选择任意片段，再点 **Generate from this passage**：程序选未用过的句子，原文直接提供答案，同一 `qwen3.5:9b` 提供干扰项。只有答案逐字还原原文、选项不同且未重复出题时才保存。

程序额外拒绝已知 SQL 非空同义写法同时充当选项，例如 `non-NULL`、`not NULL`、`IS NOT NULL`。原生成最多两次，这类选项质量问题最多再修复一次，总计最多三次调用。这不是通用语义判分，也不是迁移能力测试；它是原文记忆练习。内置原创题负责独立的诊断与迁移路线。

**仅在复现新旧配置比较时**，还需运行 `ollama pull qwen3:4b` 下载约2.5 GB的冻结旧基线模型。正常使用应用不需要这个额外模型。复现遵循最终清单记录的模型摘要和配置，不能用旧模型替代当前生产模型。

## 怎样理解评测

[v1.3最终清单](../evidence/v1.3/final-manifest.json) 是完整开发集、保留集、配置冻结和原始结果来源的依据。新比较按80条案例、两套配置组织，共160次请求；最终覆盖情况和分数以完整清单为准，不把开发阶段前缀或十道试跑结果当成最终成绩。新旧配置同时改变模型和回答检查方法，不能解释成只改变单个因素的对照实验。

Evidence 可切换新比较与原来的历史实验。新查看器默认保留集，可筛选当前配置的正确或失败记录，左右查看最终回答或错误、保存评分与理由；展开后可核对实际引用及该次请求自己的原文快照。显示投影校验原始文件哈希，只复制保存评分，不重新评分；`supported` 也不直接计作严格正确。

原 `../evaluation/` 中的80条案例、160次旧模型请求、错误与拒答保持不变；`server/ai.ts` 和原课程也冻结。它们是历史证据，不能写成 v1.3 的新成绩。旧验收文件的测试数量和交付状态仅代表对应版本。当前测试数量及浏览器、安装、断网等实际检查以 [v1.3验收记录](../evidence/v1.3/acceptance.md) 为准。

SQL 内核方法保留1600个真实 SQLite 行结果对照，以及两个依赖模型全部24个属性子集与另一种算法的核对；详见 [Lab方法](../evidence/v1.2-lab-method.md)。这里“独立”指算法不同。语义评分由编写数据集的同一 Codex 代理完成，不是盲评，也不是独立人工评审。没有真人研究、已验证提分、用户增长或获奖保证；受控模拟 API 的界面测试也不能证明真实模型质量。
